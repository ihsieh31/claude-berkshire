# 12｜自動買進三閘門、部位、加碼與賣出

> 2026-10-12 使用者核准的設計（保留自動買賣）。本檔不新設任何數字上限：部位數字全部沿用 規則書第 5、7 節（P-28、P-33、P-36、P-37、P-42、P-43、P-55），原文依據逐條附 檔名與行號。自動買進＝宿主或 agent 不再等人確認就下單；只有三閘門全過才允許。

## 1. 三閘門（缺一不可；任一不過 → 最多 `WATCH`，不得自動買）

| 閘門 | 內容 | 判定方式 | 原文依據 |
|---|---|---|---|
| 1 初篩未刪 | `screen_decision` ≠ `DELETE`（初篩只依決策日前已申報的財報判定） | 讀交接檔；欄位 `gate1_not_deleted`（由交易框架判定；`deep_quant.py` 只供研究，逐檔流程不使用） | 永不冒永久損失資本的風險 |
| 2 安全邊際 | 現價 **<** 自動買進上限＝min(P2′, `IV_base`)（SKILL §3；P2′：使隱含成長 `g_impl` ＝ 10% 的價格；等級 A／B、無紅旗、正常化盈餘 >0 才有上限） | `gate2_price_below_cap`（價格與 `g_impl` 同向，所以等價於 `g_impl` < 上限）；下單時以最新報價 ×（1＋滑價）再核一次（規則書第 7 節第 6 點） | 價值只略高於價格就沒興趣，堅持買價要有安全邊際 |
| 3 能力圈與護城河固定問卷 | `assets/gate3_questionnaire.json` 的 11 題全部作答，每題寫答案、理由與證據（來源＋日期，日期須早於決策日），且符合通過條件（護城河核心三測 ≥2 項為強） | `scripts/gate3_check.py`；結果 `gate3_pass` 寫入訊號卡與決策日誌 | 能力圈大小不重要、知道邊界才關鍵；幾乎所有決定都丟進「太難」；真正偉大的企業要有持久的護城河，需要持續重建的護城河最後等於沒有 |

- 三閘門是**自動買進的授權條件**，不取代 SKILL §2 的 G0–G11 流程：BUY 仍須 G0–G11 全過、G8 勝出、論點檔已存、G9 無紅燈。閘門 3 的題目就是 G1（能力圈）與 G3／護城河的固定化作答格式。
- **問卷的目的是事後可稽核**：題目、選項、通過條件固定，不得因個股增刪；答案與理由逐字存檔（決策日誌，`procedure/13_forward_validation.md`）。日後驗屍時比對「當時怎麼答、根據什麼」，評決策不評結果（規則書第 8 節）。
- 作答前不得看價格（價格最後看，規則書CORE-03、PROC-044 ②③）；問卷必須聲明 `price_seen_before_answering: false`，否則閘門 3 不過。
- 「不知道」是合法答案，但會讓閘門 3 不過（落入太難）。
- 問卷通過不提高等級：C1 只到「5 到 10 年」→ 最高 B；M6＝「良好」→ 降一級（P-01、SEL-055）。

## 2. 部位：小首批，論點成立才加

```
目標權重 T = G11 公式（procedure/06_certainty_position.md §3）＝ min(意願權重, P-28 等級上限, P-29 尾部, P-30 單事件, P-31／P-32 相關群, 宿主上限)
  P-28 宿主等級上限：A 15%／B 10%／C、D 不開倉
  T < 3% → 不建倉（P-33；不試水溫）
首批 = 0.5 × T # P-36 首批＝目標 50%；自動模式不使用「距 52 週高點 ≤ −20% 可到 70%」的加速條款
剩餘 0.5 × T：P-37 窗口（1–15 個交易日）內分批，每一批下單前都要通過「加碼許可」（下表）；窗口到期或連 10 日高於上限 → 取消剩餘批次（P-37）
到達 T 之後的加碼：P-42 門檻＝新建倉門檻（三閘門以當次資料重新全過）
```

**加碼許可（每次複查都檢查；由交易框架判定，`deep_quant.add_allowed` 只供研究）**：
| 條件 | 不成立時 | 出處 |
|---|---|---|
| 本次論點檢查結論＝完好（H1 複查＋H2 Q2；失效條件無一出現） | 停止加碼；疑似 → P-50 觀察 | 規則書P-55、P-50；原文：因新聞下跌而生意不變就加買，在下跌前已買一部分、仍歡迎下跌並加買 |
| 三閘門以本次資料重新全過 | 不加碼 | P-42 |
| 價格 < 買價上限 | 不加碼（不追價） | NEVER-11 |
| 現有市值權重 ≤ 15% | 不加碼；>25% 完整複查 | P-43 |
| 現有權重 < min(T, P-28 等級上限) | 已到上限不加 | P-28 |

- 為什麼首批不是全部：規則書把首批比例定為**執行節奏**，不是試探部位（CORE-11）；目標部位在建倉前就算好，且 ≥3%，所以首批 50% 不是 start_small。原文：找到符合標準的少數公司時，應該買有意義的量；懂生意的投資人持有五到十家就夠，不必分散。
- 為什麼加碼要以論點為條件：原文的加買理由是「生意沒變、價格變便宜」，不是「已經持有所以加」；規則書加碼禁止條款（為扳平加碼惡化中的生意、觀察中部位、低信念邊緣部位）照用（規則書第 7 節「加碼」）。
- 一般模式（非宿主）的大資金上限（A 40%／B 20%）與原文單一持股可達四成只適用 規則書一般模式，**自動買進一律用宿主上限**。

## 3. 賣出

- 停損模式只有 `stop_mode`＝`A_THESIS_CHECK`：**沒有價格停損、沒有移動停損**；跌幅只觸發論點破裂檢查（P-55 (a)–(e)），論點被證偽才全清（P-52 速度）。
- 其他賣出只走 規則書H2（Q2 論點、Q3 估值 P-45～P-48、Q4 只轉弱、Q6 換股）；跌價本身永遠不是賣出理由（NEVER-09）。原文：因可怕新聞賣掉好企業通常是壞決定。
- 不得做：價格停損、移動停損、賣出後把資金自動停泊在大盤指數基金（SPY 停泊）、以已否定的硬篩（硬篩 ROE、零虧損、固定本益比上限、單年 EPS 下滑賣）作賣出觸發。這些都已被否定（規則書第 7A 節、第 10 節）。

## 4. 宿主自動下單前的最後自檢（全部「是」才送單）
1. 三閘門 `gate1_not_deleted`、`gate2_price_below_cap`、`gate3_questionnaire` 皆為 true，且問卷檔路徑寫在訊號卡。
2. 首批或本批金額 ≤ 計算值（首批 0.5 × T；之後依加碼許可）。
3. 限價 < 買價上限；最新報價 ×（1＋滑價）< 上限。
4. 當日新部位 ≤4（P-44）、持股 ≤ 宿主上限、可動用現金扣已承諾後足夠（P-35）。
5. 決策日誌已寫入本次決策（`procedure/13_forward_validation.md` §2 欄位）。
