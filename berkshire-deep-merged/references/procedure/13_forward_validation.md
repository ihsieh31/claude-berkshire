# 13｜前瞻紙上交易驗證

> 為什麼要做：自動買進的閘門 3（能力圈與護城河問卷）無法用歷史資料回測，閘門 1＋2 的歷史描述也被多輪研究看過（ §2、§3）。唯一乾淨的檢驗是**往前跑**：規則先凍結，再看之後發生什麼。期間 3 個月是使用者 2026-10-12 指定的長度；3 個月不足以判斷報酬好壞，只能檢查流程是否照規則執行、記錄是否完整、閘門是否擋對東西。

## 1. 規則
1. **開跑前凍結**：記錄兩個 skill 全部檔案 sha256 與問卷版本；3 個月（使用者指定）內不得改規則、門檻或題目。發現程式錯誤可修，但要記錄修改日期、原因與受影響的決策。
2. **紙上交易**：不動用真實資金；成交價以決策後下一個交易日的典型價 TP＝（高＋低＋收）÷3 記帳（紙上交易近似；依 SKILL §5 避開開盤，設計決策 D07）：市價買 TP ×（1＋滑價）、市價賣 TP ×（1−滑價）；限價買單在當日最低價 ≤ 限價時成交，價＝min(TP ×（1＋滑價）, 限價)；限價賣單在當日最高價 ≥ 限價時成交，價＝max(TP ×（1−滑價）, 限價)，未觸及即作廢（當日有效）。
3. **每一個決策都記**：買、加碼、持有、賣、觀察、不買全部寫入決策日誌，包含閘門沒過的。不能只記買進。
4. **決策日與資料時點**：每筆記錄寫決策日、使用的財報申報日、價格日期；申報日必須早於決策日。

## 2. 決策日誌欄位（`assets/decision_log_schema.json`；一筆決策一列，JSON Lines）
| 欄位 | 內容 |
|---|---|
| `decision_id`、`decision_date`、`time_zone` | 唯一編號、決策日、時區 |
| `ticker`、`action` | 標的（只出現在日誌）、BUY／ADD／HOLD／SELL_ALL／TRIM／WATCH／NO_ACTION |
| `skill_hashes`、`questionnaire_version` | 凍結雜湊、問卷版本 |
| `screen_decision`、`delete_reason`、`flag_codes`、`distress_codes`、`fy_last_filed` | 初篩結果與時點 |
| `gate1_not_deleted`、`gate2_price_below_cap`、`gate3_pass`、`gate3_failures` | 三閘門結果與不過的原因 |
| `gate3_answers_file` | 問卷作答檔路徑（11 題的答案、理由、證據原文存檔） |
| `grade`、`g_impl`、`r_d`、`buy_price_cap`、`price`、`price_date`、`price_to_cap` | 等級、估值與價格 |
| `target_weight`、`tranche_weight`、`portfolio_weight_after` | 目標、本批、成交後權重 |
| `thesis_check`（完好／疑似／證偽）、`failure_conditions_hit`、`review_trigger_hit` | 論點檢查（持有、加碼、賣出時必填） |
| `reason_one_liner`、`stopped_at_gate`、`rule_ids` | 一句話理由、停在哪關、規則編號 |
| `fill_price`、`fill_date`、`slippage_assumed` | 紙上成交 |

## 3. 3 個月後的檢討（固定格式，事先寫定、不看結果改格式）
1. **流程合規**：日誌筆數 vs 實際決策次數；欄位缺漏率；有沒有任何 BUY 缺閘門紀錄、問卷理由或證據；有沒有用到決策日之後申報的資料；有沒有價格停損或移動停損類的賣出（應為 0）。
2. **對大盤**：紙上組合 vs 大盤指數（含股利）的報酬差；同期每筆買進自成交日起的報酬 vs 大盤。
3. **對初篩保留母體**：同一個股票池裡，初篩保留但未被買進的股票，在同期間的平均與中位報酬（等權）——用來回答「三閘門有沒有比『只刪垃圾』多挑出東西」。另報初篩刪除那一群的同期報酬（預期：兩邊尾巴都較肥）。
4. **閘門診斷**：各閘門擋下的數量；閘門 3 不過的題目分布；問卷「強」與實際走勢是否有明顯矛盾的個案（只記錄，不改題）；閘門 2（現價 < 自動買進上限）擋下、之後明顯上漲的 A／B 級個案另列，作為 `cap_discount_k`（A 0.95／B 0.85）的檢討依據——紙上期內不調 k（`09_postmortem_signals.md` 錯誤二反面陷阱）。
5. **誠實標示**：3 個月（使用者指定）樣本小、受市場整體行情左右；任何結論只到「流程可用／不可用」，報酬差只作參考，不得據此放寬或收緊門檻。要改規則，須另寫測試規格、在新的期間再驗證。

## 4. 結束條件
- 3 個月到期、或使用者喊停；任何一筆違反「三閘門全過才買」或「沒有價格停損」→ 立即停止並檢討。
- POS-064（rulebook 宿主模式列「最後 5 個交易日不開新部位」）：紙上期沒有清算日，評估期到期不是買賣理由，此條不適用、框架不實作；日後若定出評估結束日再實作（設計決策 D94）。
