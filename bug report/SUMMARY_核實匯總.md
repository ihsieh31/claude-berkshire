1. 五份報告**沒有發現會直接造成錯誤成交的缺陷**：下單前 `sizing.plan_buys` 會用訊號卡上限再檢查一次「報價×(1＋滑價) < 上限」，C／D 級的目標權重是 0。買進這一側是保守的。

## 4. 成立但影響很小（排進例行維護即可）

- 等級 C／D 或缺等級的持股，權重超限時不會減碼，註解寫「僅記錄」但實際上什麼也沒記（deepseek C3、qwen N-3）：`sizing.py:414-416`。
- 登錄表的 `weight` 是分析當時的靜態值，`review_due` 的「低於目標權重」觸發與 `_map_action` 會一直判成要加碼 → 只會多跑幾次 PRICE（haiku），不會超買（deepseek D5、qwenhigh G14）。
- `ledger adjust --set-qty 0` 不會取消該檔的未成交買單（deepseek1m P0-5，**原報告列 P0，我降為低**：已下市的代號沒有 bar 可以撮合；但還是應該順手取消，約 3 行）。
- 金融股或直接給 `iv_cons` 時，結論測試的「E×0.9」那一半沒有作用（`cap_calc.py:116-118`；deepseek B3、qwen P1-7、qwenhigh M2）。1 行。
- 拆股後訊號卡的 `auto_buy_cap` 不會跟著換算（登錄表與 cap_inputs 有換算），而 `plan_buys` 讀的是訊號卡（qwenhigh G7）。要等下一次 PRICE 才會更新，發生的時間窗很窄。
- 公司行動的「市值守恆」檢查用的是由比例反推的價格，幾乎一定會通過；比例與價格比的容差 15% 偏寬（qwenhigh Z4，**原報告列致命，我降為低**：Alpaca 有提供比例時，另有 0.1% 的比對；只有 8-K 來源的拆股才只靠這一關）。建議容差改成 3%。
- HOLD_REVIEW 的 `path[].q` 列舉沒有 Q3b／Q3c，提示卻要求「TRIM 只用於 Q3c」（qwen P0-8，**原報告列 P0，我降為低**：寫錯會重試，最壞是保守的 HOLD）。在列舉裡補上即可。
- 月報的「決策日後申報」「skill 雜湊」兩項檢查讀的欄位框架從來不寫 → 永遠顯示 0（qwenhigh G5）。
- `trader.jobs.review_jobs` 單獨 import 時會因循環匯入失敗（qwen N-13，已實測；CLI 正常）。
- `router.build_runner` 建 deny 清單時沒有帶 `state_dir`（qwen P1-1、qwenhigh M14）：只有用 `--state-dir` 指到專案外面時才有影響。1 行。
- 只影響回測或補跑：P/E 中位凍結檔沒有檢查檔內 asof、股票池沒有 asof、`_gate3_status` 查詢沒有時點上界（qwen P0-6／N-11、qwenhigh G8／G18）。系統是往前跑的紙上交易，**原報告列 P0，我降為低**。
- 文件：`rule_index/04_hold_sell.md:163` 仍寫 40 倍（雖然檔頭有覆寫聲明）；`procedure/12` 還把 `deep_quant.py` 當成閘門腳本，但 SKILL 寫「逐檔流程不使用」。
